Preprocessing

Training, in the notebook
  • Raw TotalCharges converted to numbers; rows where it was blank were dropped.
  • customerID removed (an identifier, not a feature).
  • Churn converted: Yes = 1, No = 0.
  • Stratified 80/20 train-test split before encoding.
  • One-hot encoding with drop_first=True; test columns aligned to training columns.
  • StandardScaler fitted on the training data only, then applied to the test data.

Prediction app inference

What app.py does for each request
  • Validates all 19 fields (allowed values, tenure 1-72, monthly charges 0-200, total charges 0-10,000).
  • If total charges is blank it is estimated as tenure x monthly charges, and the result says so.
  • Builds the same 30 columns in the same order as training (saved in feature_columns.json).
  • Applies the saved scaler, then the saved model weights.
  • Explanation = weight x scaled value for each feature, versus an average training customer.

Limitations

Read these before trusting a score
  • Recall is only about 0.57, so roughly 4 in 10 churners are missed at the 0.50 threshold.
  • One train-test split only. No cross-validation, so the metrics have no error bars.
  • Probability calibration has not been checked, so a score of 60% may not mean 60% in practice.
  • Fairness across groups (gender, age and so on) has not been evaluated.
  • Trained on one public telecom dataset. It may not transfer to another company or period.
  • Tenure, monthly charges and total charges are strongly correlated, so individual factor bars should be read together.
  • Patterns are correlations. A high churn rate in a group does not prove the attribute causes churn.
  • Flask development server with no login. This is a student project, not a production system.

Data privacy

What this app does with data
  • The training data is the public IBM Telco sample dataset. Customer IDs are removed before training.
  • app.py does not write submitted customer details to disk or a database.
  • Fonts and Chart.js are loaded from Google and jsDelivr, so the browser contacts those servers.
  • If this were used with real customer data, add authentication, access control, and a data-protection review first.
